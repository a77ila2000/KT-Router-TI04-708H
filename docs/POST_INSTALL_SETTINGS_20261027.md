# 2026-10-27 설치 후 통신·LED·화면 설정

이 문서는 이미 OpenWrt25.12.6이 NAND에 설치된 개발 실기의 후속 설정이다. 처음 설치할 때는 [설치 안내](../INSTALLATION.md)를 따른다. 새 펌웨어 릴리스나 다른 순정 장비에서의 전체 설치 재현 성공을 뜻하지 않는다.

## 현재 기능과 검증

| 기능 | 결과 | 한계 |
|---|---|---|
| WAN·연결된 LAN | 각각1Gbps 전이중, DHCP WAN 주소/기본 경로·DNS·HTTPS·NAT 통신 | 미연결 LAN3개는 실제 케이블 시험 없음 |
| 유선 인터넷 | 각8MiB 다운로드71.72Mbps·업로드60.20Mbps | 짧은 인터넷 관측값, 최대 처리량 아님 |
| 2.4GHz 인터넷 | 각4MiB 다운로드45.60Mbps·업로드30.93Mbps | 채널1/HT20, KR, 소프트웨어10dBm |
| 5GHz 인터넷 | 각4MiB 다운로드71.10Mbps·업로드50.49Mbps | 채널36/VHT80, KR, 소프트웨어10dBm |
| 외부 ping | 최종20회 전부 응답, 손실0%, 6–8ms | 장기 안정성 시험 아님 |
| WAN LED | 연결·송수신 트리거 적용, 사용자 실물 반응 확인 | 인터넷 도달 여부가 아니라 Ethernet 링크/트래픽 표시 |
| LAN LED | 번호 매핑 확인, 실제 LAN4 점등·활동 점멸 사용자 확인 | LAN1~3 케이블 이동 시험 없음 |
| 공용 Wi-Fi LED | 두 대역 각각 활성화·통신 시 밝기 변화, 비활성화 시 소등 | 소프트웨어 샘플 확인; 물리 시각 확인과 구분 |
| NTP | 누락 구성 보완, 서비스 실행, UTC 오차5초 이내 확인 | 기존 UBI 이미지에는 미포함 |
| 무선 대역 표시 | 별도 view 경로의2.4/5GHz 표시 사용자 확인, 메뉴 권한 보존 검사 통과 | 이번 변경 후 물리 냉간 부팅 미시험 |

무선 트래픽은 PC Wi-Fi 소스 주소·경로·실제 어댑터 카운터와 공유기의 해당 단말 연결 기록을 함께 검사했다. 어댑터 오류 증가는 없었다. 마지막 두 라디오는 시험 전 disabled 상태로 복원했고 시험 AP와 Windows 임시 프로필을 제거했다. 실제 RF 출력과 수신 범위는 측정하지 않았다.

## LAN 번호 정정과 최종 LED 구현

개발 초기의 ‘실물 LAN1’ 표기는 실제 번호를 확정한 결과가 아니었다. 이번 사용자가 노트북 케이블 위치를 **실물 LAN4**로 확인했고, 시스템에서도 `lan4` carrier가1이었다. 별도 강제 LED 시험은 PHY1~4 순서에 대해 표시등 **LAN4→3→2→1** 순서를 확인했다. 이를 상태 인터페이스와 별도로 매핑했다.

LAN LED1 force 모드는 미연결0x8000 / 연결 대기0xa000 / 활동0xe000을 사용한다. 최초 LED0의 1Gbps 패턴 보완은 눈에 보이는 LAN 표시등에 효과가 없었고0x0630 초기값으로 되돌렸다. 다른 PHY 설정·커널·부트로더를 바꾸지 않았다. 최종 서비스는1초마다 각 포트의 carrier/송수신 바이트를 읽으며 WAN은 기본 `netdev` 트리거, Wi-Fi는 두 대역 합산 상태를 사용한다.

[LED·NTP 소스와 적용/제거 방법](../device-settings/README.md)을 공개한다. 실기에서 실행 중인 최종 소스와 서비스를 보존했으며 바이너리 대신 빌드 절차를 제공한다. 자동 시작 등록은 확인했지만 LED/NTP 후속 변경의 물리 냉간 부팅은 이번에 시험하지 않았다.

## 관리자 화면

- Argon3.1.0·한글 기본·English 선택은 이전 검증대로 유지했다.
- [출력 프로필](../luci/README.md)은 현재 드라이버 허용 범위의 자동/수동 상한이다. 구형35dBm 고정 요청 드라이버를 적용하지 않았다.
- 무선 목록의 대역을 실제 `band` 값으로 읽어 큰 이름으로 표시하고 내부 식별자를 작은 글씨로 남기는 수정 파일을 적용했다. 네트워크·무선 설정 파일 SHA는 불변이었다.
- 서버의 새 JS SHA 일치만으로 사용자 화면 완료를 단정했던 부분을 정정한다. 강제 새로고침 후에도 기존 표시가 남아 실제 band 값과 로딩 경로를 조회했다. 설정은 정상이었고, 별도 `network/ti04-wireless-bands` 리소스 경로와 실행 상태의 band fallback을 적용한 뒤 사용자가 정상 표시를 확인했다. 최초 현상의 정확한 원인은 미확정이다. 원래 vendor `wireless.js`는 복원했고 메뉴의 action 경로만 바꿨다.

## 실패·제약과 조치

| 시도 | 결과·조치 |
|---|---|
| 5GHz 첫 HTTPS 전송 | 수신 reset1회. 독립 재시험은 curl 재시도 없이 양방향 성공. 최초 원인은 미확정 |
| AP 종료 로그 | ath10k beacon callback/peer 경고 관측. 수집한 구간의 firmware crash는 미관측. 경고를 없었다고 쓰지 않음 |
| 같은 UCI 세션의 복원 판정 | staged 값이 남아 불명확. 새 인증 세션에서 원래 설정과 비활성 상태를 대조 |
| LAN LED0 패턴 | 실물 LAN 표시등 반응 없음. 초기값 복구 후 실제 LED1 채널 조사 |
| 첫 LAN 강제 점등 | 실제 연결 포트와 무관한 채널 시험이었다. 연결 반응 성공으로 표시하지 않고 번호 순서를 다시 확인 |
| Wi-Fi 소수점 sleep | 장비 기본 sleep 미지원. 해당 프로세스 중지 후 정수 조회+커널 timer로 수정 |
| 비밀번호 입력창 재사용 | 도구 승인 검토에서 차단. 기본 SSH 창에 사용자가 직접 입력하는 방식으로 전환, 정책 설정 변경 없음 |
| 표시 파일 첫 전송 | 장비에 base64 명령이 없어 설치 전 중단. 원본 유지, tar 바이너리 직접 전달로 변경 |
| 같은 경로의 무선 JS 수정 | 서버 SHA는 일치했지만 사용자 화면은 기존 표시. 별도 view 리소스 경로 적용 후 사용자 정상 표시 확인 |
| SSH 진단 대기 | 비밀번호 입력 대기 중 연결 종료. 사용자 직접 로그인한 SSH 연결을 작업 중 유지한 뒤 진단·수정 완료 후 종료 |
| Windows 명령 전달 | 인용문 오류로 SSH 전송 전 중단. 바이너리 stdin의 원본 SHA 보존 확인 후 재실행 |
| 소프트웨어 종료 | poweroff/halt 뒤 자동 재부팅. 완전 전원 차단은 어댑터 분리 필요. 재시작 원인은 미확정 |

계정/암호·SSH 키·세션·MAC·SSID·실제 WAN 주소·원본 로그·NOR/NAND/ART·개인용 이미지는 이 문서에 포함하지 않는다. 작업용 인증 정보와 SSH 키는 사용 후 삭제/폐기했다. 저장소의 미검증 실험 아이디어는 [보존본](../RESEARCH_NOTES.md) 그대로 유지한다.

## 배포에 남은 작업

별도 overlay인 LED/NTP/UI 설정을 새 배포 빌드에 포함하고, 개인 정보 없는 이미지·manifest·모델/범위 검사와 함께 다른 순정 장비에서 처음부터 재현해야 한다. 이번 후속 통신 성공으로 WAN 항목은 갱신하지만, 물리 냉간 부팅·다른 LAN 포트·최대 성능·RF 측정·장기 안정성·완전 복원은 남은 검증으로 기록한다. 무선 대역 이름의 시각 확인은 이번 후속 수정에서 완료했다.
